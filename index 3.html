About This Collection

I chose cloud security and cybersecurity because I already had some interest in the topic, but I did not realize how much actually goes into keeping cloud systems secure. As I started finding sources, I noticed that security problems are not always caused by major cyberattacks. Going through the different sources also showed me how many decisions can affect the security of a cloud system. This made me more interested in understanding what organizations have to pay attention to when using cloud services.

When putting the collection together, I wanted the sources to build on each other instead of feeling like a group of unrelated articles. I started with sources that explain cloud computing and its basic security concerns, then moved into topics that became more specific as I continued my research. These include vulnerabilities, secure design, protecting data, shared responsibility, and ways organizations manage cybersecurity. I also included different types of sources so the collection would not rely on only one perspective. These include government publications, technical guidance, professional frameworks, research, a book chapter, a podcast, and a video.

As I worked on this collection, I noticed that a lot of the sources connected to each other even though they focused on different parts of cybersecurity. Some sources helped me understand the more technical side of cloud security, while others made me think more about the decisions organizations have to make when using cloud services. I also learned that cloud security is a much broader topic than I originally thought. Putting these sources together helped me understand how the different areas of cybersecurity can affect one another and gave me a better overall understanding of the topic.

Link to Source

The OWASP Top 10 lists some of the security issues that show up most often in web applications. I wanted to include this source because I kept seeing topics like access control and security misconfigurations while researching other parts of cloud security. Data Protection and Shared Responsibility

Government security and privacy report

Guidelines on Security and Privacy in Public Cloud Computing

National Institute of Standards and Technology (NIST)
Link to Source

This NIST source focuses on security and privacy concerns that can come with using public cloud services. I included it because it helped me understand that moving information to the cloud does not mean an organization no longer has to worry about how that information is protected. Organizations still have to think about things like who has access to their data, how it is being protected, and what responsibilities belong to them and the cloud provider. I thought this connected well with the shared responsibility sources in my collection because they discuss some of the same concerns from a different perspective. It also made me think more about privacy as part of cloud security instead of only focusing on cyberattacks or technical problems. This source was published in 2011, so some of the information is older. I still found it useful for understanding the security and privacy concerns organizations should think about when using public cloud services.

Cloud provider documentation

AWS Shared Responsibility Model

Amazon Web Services (AWS)
Link to Source

Something I found interesting about AWS is that using their cloud services does not mean AWS handles every part of security. The customer is still responsible for things like their data, accounts, applications, and some of the security settings they choose. AWS, on the other hand, is responsible for the infrastructure that its services run on. This is known as the shared responsibility model. I added this source because this idea came up several times while I was researching cloud security, and I think the AWS example makes it easier to understand. It also shows why an organization can still have security problems even when the cloud provider itself is secure. The responsibilities can also change depending on which AWS service is being used. Since this page is specifically about AWS, I would not assume that every cloud provider divides responsibilities in exactly the same way.

Cloud provider documentation

Shared Responsibility in the Cloud

Microsoft Azure
Link to Source

This Microsoft source shows how security responsibilities can change depending on the type of cloud service being used. It compares on-premises systems with IaaS, PaaS, and SaaS, which helped me see how the customer's role can become different as more of the system is managed by the cloud provider. Even when the provider takes care of more of the technology, the customer is still responsible for important areas like their data and accounts. I included this source because it connects directly to the AWS shared responsibility model, but shows the same idea through another cloud provider. Comparing the two made it easier to see that shared responsibility is not something that only applies to AWS. I also thought the comparison between the different cloud service models was helpful because it shows that responsibility is not divided the same way in every situation. Since this source is from Microsoft, some of the details are specifically related to Azure.

Security Management, Frameworks, and Practice

Cybersecurity framework

The NIST Cybersecurity Framework (CSF) 2.0

National Institute of Standards and Technology (NIST)
Link to Source

The NIST Cybersecurity Framework 2.0 gives organizations guidance for handling cybersecurity risks and improving their security practices. I included this source because it is different from the sources in my collection that focus mainly on cloud systems or individual security problems. A part that stood out to me was how the framework breaks cybersecurity into different areas instead of treating it as one task. It shows that organizations need to think about what they will do at different stages of a security issue, including before a problem happens and after one has already occurred. I think this source fits well in my collection because it gives a broader view of cybersecurity and connects to several of the more specific topics covered in my other sources. One limitation is that it does not explain exactly how to configure or secure a particular cloud service.

Cloud security control framework / assessment tool

Cloud Controls Matrix (CCM)

Cloud Security Alliance (CSA)
Link to Source

The Cloud Controls Matrix brings together a large number of security controls that can be used when working with cloud systems. It covers areas like data security, identity and access management, infrastructure, logging, and incident management. I included this source because it showed me how many different parts of a cloud environment have to be considered when thinking about security. What stood out to me was that cloud security is not really one specific task or control. There are many different areas that have to work together. I also thought this source fit well with the NIST Cybersecurity Framework because both organize security into different areas, but the CCM is more focused on cloud computing. The amount of information in the matrix can be a little overwhelming at first, especially for someone who is new to the topic. However, I think it gives a good example of how detailed cloud security management can actually become.

Security benchmark / configuration guide

CIS Amazon Web Services Foundations Benchmark

Center for Internet Security (CIS)
Link to Source

This CIS benchmark gives recommendations for security settings that can be used in AWS. I included it because it is more focused on actual cloud configurations than some of the other sources in my collection. This connected to my earlier research on configuration mistakes because it gave me a better idea of what those types of mistakes could involve. I also thought it was useful to have a source that shows a more practical side of cloud security instead of only discussing it from a broader perspective. Since the benchmark is made specifically for AWS, the recommendations would not apply exactly the same way to every cloud platform. Organizations would also have to consider their own systems and security needs when deciding which recommendations to follow.
